## 优化

### 消除启动白屏

此前窗口在内容渲染完成前就显示了。plainmark 基于 Tauri，启动时需先初始化 WebView2、加载脚本、挂载界面，这段空白期会以白屏形式暴露出来。

现在窗口初始为隐藏，首屏渲染完成后才显示——你看到的第一帧就是完整的界面。

同时加了兜底机制：若前端因异常未能显示窗口，3 秒后会强制显示，确保应用始终可用。

### 缩短启动时间

- 启动路径上的 6 次串行等待改为并行，IPC 往返从 6 轮减少到 1 轮
- 预览渲染器（markdown-it + DOMPurify，约 128 KB）改为按需加载，首屏 JavaScript 从 784 KB 降至 638 KB（减少 17%）

### 关于启动速度的说明

plainmark 的启动速度无法与 Windows 记事本完全一致。记事本是原生 Win32 程序，窗口创建时控件已就绪；而 Tauri 应用需要先启动 WebView2 运行时再渲染界面，这段固定开销无法消除。

本次优化解决的是「白屏」这一观感问题，让界面出现时即是完整可用的状态。

## 已知限制

- 打印与页面设置尚未实现，菜单中不提供
- 字体对话框为自建界面（WebView2 无原生字体选择器），与记事本存在细微差异
- 查找 / 替换使用编辑器内置面板，尚未做成记事本的中文独立对话框
- 不接管 `.txt` 关联，避免抢占记事本的默认地位
- 预览中的远程图片（如 shields.io 徽章）会联网加载
